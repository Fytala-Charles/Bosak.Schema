# Default groups on existing noninteger simple-content extensions

Both owned native facades support active schema default groups on already-supported noninteger simpleContent/extension owners. Original governing complex G remains distinct from actual simple/compound content A and original list/union member identities. Named/inline and existing nested owner routes retain their original source namespaces and declarations. Default/explicit group repeats deduplicate by actual identity; distinct same-name uses remain Invalid.

Existing noninteger scalar and compound value mappings are reused. This change does not add new primitives, identity binding, derivation, lexical rules, equality or value representation. Required uses remain required; optional absence is supported; missing default/fixed values remain Unsupported because they require augmentation. Provided values and XML remain original. Existing effective-use16, source/schema/string/regex/depth/atom/value/lifetime limits remain.

Integer extension attributes and Boolean extensions remain unsupported. Simple-content restrictions, complexContent/general complex-base inheritance, active wildcard/mixed/assertion combinations and the separate opt-out closure do not expand. No synthetic type/declaration, source clone, acquisition route, public API/Core change or publication is included.

Complete assessment precedes facts. Native proofs verify actual G/A/member and attribute provenance, canonical group/global identity, no-facts failures, recovery, cancellation, detached values, foreign ownership and expiry. Original upstream samples and the invoice consumer workflow are separately measured; none constitutes a normative coverage percentage or production acceptance.
