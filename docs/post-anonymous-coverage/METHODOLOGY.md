# Review method and practical limits

The complete selected set is every existing Unsupported row in the two frozen structural cohorts and the 598-case datatype cohort. Original source metadata/validities and all fixture hashes are unchanged at upstream xsdtests revision 7bc3365c652a322f3d762021b3879eb92dae7e30. 80 IDs map to 65 distinct schema byte sequences. Source XML and current guards were reviewed for every schema. The sixteen primary groups are exclusive; extra blockers are deliberately nonexhaustive.

The previously qualified local package DLL and nine signed Core 1.86.0 runtime payload hashes were verified before launching a diagnostic. The existing public runner was used unchanged. A separate caught diagnostic, built as a test friend assembly, reads internal refusal detail from the same Schema DLL; it confers no public component authority and changes no engine behavior. Its source is archived as Diagnostic.cs.txt. Both public and detailed observations reproduce all 80 refusals: 79 compile and 1 assessment. The compile-success anyType case refuses xsi:type during assessment. No failures are launched outside caught/test harnesses.

The first public request used host-relative instance paths from a worktree launch. Only the compile-success case reached that path and reported a caught DirectoryNotFoundException. Absolute paths corrected the private request; all 80 original cases were rerun, with zero errors. The initial output and compilation-only detail are retained in EXECUTION-EVIDENCE.zip alongside final receipts. No fixture or product rule was changed for this correction.

Full source 29,374, internal 2,111 / public 27,263, exact-package 27,263, API 55/663, signed Core and full original cohort/invoice receipts are reused from the sealed anonymous-floating-bases qualification. They are not new full-suite or full-cohort runs in this review. New PR/main CI verifies the documentation tree separately; its delivery IDs are recorded in the private completion receipt. Source/test/build inputs match the prior qualification with only exact repository LF/CRLF checkout normalization accepted.

The 28-area matrix does not enumerate every normative requirement and marks no area fully conformant. It corrects inherited local evidence references and stale qualification metadata in a new matrix, preserving original matrices/receipts. Review pins do not replace historical semantic-adoption records. Historical Core evidence remains explicitly historical, and public C45/PSVI acceptance is still pending.

Composition cases were executed through the original single-text API. The existing closed catalog API already supports bounded includes and named-simple-type imports. Eleven selected cases reference composition across eight schema roots; required dependency files are absent in the frozen directories or an import lacks schemaLocation. No network resolution, invented dependency text or catalog admission forecast is made. Foreign complex imports/chameleon/redefine/versioning remain distinct obligations.

Normative review uses the dated REC 2012 Structures/Datatypes, XDM 2017 and dated XML/Namespaces pins in REVIEW-PINS.json. QName length validity is reviewed against Datatypes 4.3.1.3 / 4.3.2.3 / 4.3.3.3, while component and fixed/inherited facet constraints still apply. Full normative adoption is required before implementing that separate scope.
