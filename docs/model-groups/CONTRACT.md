25 November 2026; authorized batch slice13. This contract is adopted at the exact verified slice12 main revision recorded in ADOPTION.json before production changes.

Admit closed named sequence groups at a complex owner's top content particle and nested group references inside an admitted sequence. Only group use minOccurs=maxOccurs=1 is admitted; source element particle bounds retain their existing rules. Flatten sequence membership for finite routing without copying source XML or creating per-owner authoritative element declarations: actual source element particle/declaration objects are cached and reused across group owners. Global element refs retain their canonical global declaration. Group-local types and anonymous type identity remain shared. No group PSVI/public lookup API is added.

Group definitions and references resolve eagerly, including unused groups, and closed forward dependencies cache their flattened source particle arrays. Groups contain exactly one sequence; sequence source members are admitted elements or group refs. Each group definition/reference QName uses actual source namespace bindings; groups use targetNamespace, while local element form continues to use the schema default/explicit form. Malformed/empty/unbound references and illegal ref+name combinations are Invalid. Missing closed definitions remain Unsupported. Circular model-group references are Invalid under Structures3.8.6.1, unlike permitted circular attribute groups. Element/type recursion remains separately Unsupported.

Definitions/raw sequence members/expanded particles cap16 each; source QName256 and current nested node/scalar/depth/attribute budgets remain. Sequence group nesting can only traverse the16closed definitions, and detected cycles terminate before expansion. Repeated same-name element particles remain Unsupported in the current finite router; this is not a general XSD invalidity assertion. Empty groups, all/choice groups, optional/repeated group uses, nested compositor trees, wildcards, annotations, imports/redefine/override remain separate. Existing attribute uses/groups and structural-assertion exclusion retain their boundaries. Legacy grammar, public API, Core payload and publication remain unchanged.
