# M1 adoption: namespace-aware finite decimal assessment

Recorded before implementation,19November2026. Baseline public Schema3ff8cb6 and Coref7b6c995. User requested continuation of shared specification-coverage priority. This adopts only the behavior below, not full XSD1.1 or a general provider API.

Immutable body receipts are in SPECIFICATION-SOURCES.json. XSD1.1 Structures20120405 sections2.6,3.3.2/3.3.4,3.4.2/3.4.4,3.8,3.9,3.13 and4.2: root declaration target namespace, local element form defaults/overrides, ordered assessment and zero-to-eight bounded assertions. XPath2.0 secondedition20101214 sections2.1.1,2.3,3.2 and3.5/3.6: QName static resolution, default element namespace and existing child comparisons/logical behavior. Namespaces1.0 thirdedition20091208 sections2.1/2.3,4,6.1/6.2: expanded-name identity, exact URI string comparison, prefix scoping/defaulting. Structures/XPath downloaded hashes match the original adopted bodies; the new namespace body hash is separately pinned. Original adoption records and old review/source pins stay unchanged.

Schema grammar adds targetNamespace and elementFormDefault(qualified/unqualified, defaultunqualified), plus local form override. Global root namespace is targetNamespace or absent. Local namespace is targetNamespace only when effectively qualified. Names match namespace URI plus local name, never a prefix or normalized URI. Existing unqualified behavior is preserved. Duplicate expanded child names still refuse; distinct expanded names with equal local parts may coexist. Named types, references, imports, attributes, nil, wildcard/choice/nested content and other previous exclusions remain outside M1.

The finite assertion grammar accepts QName child operands, resolved in the assertion element's in-scope namespace bindings. Unprefixed operands use assertion xpathDefaultNamespace, else schema setting, else local. Admit ##local, ##targetNamespace, ##defaultNamespace and explicit absolute URIs; namespace URI strings remain case/escape-sensitive. ##defaultNamespace uses the in-scope default binding where that setting is declared. Undefined prefix, malformed/unknown child QName and unknown assertion syntax refuse schema compilation, never select a same-local-name child. Function words stay positional unprefixed built-ins; no arbitrary functions or XPath syntax. Prefix shadowing must use the actual assertion context. Numeric constants are not QName operands.

Target/default namespace lexical strings use XML whitespace collapse. As an intentional finite-profile restriction, nonempty namespace URI values must be absolute and not contain whitespace; relative/reserved XML/XMLNS/XS/XSI target namespaces refuse as Unsupported. This is not a claim that every such restriction is required by XSD. Empty explicit targetNamespace and invalid form settings refuse as Unsupported rather than being ignored. XML namespace declarations and xml: prefixed names still obey the XML parser. All input/numeric/token/depth/byte/admission limits remain.

An anonymous complex type can carry sequence followed by zero-to-eight assertions; remove only the old minimum-one assertion restriction. Invalid schema/instance versus Unsupported boundaries otherwise stay as before. Namespaced instances valid under newly admitted schemas may now be Valid; wrong namespaces under either new or old schemas remain Invalid. Diagnostic examples formerly using targetNamespace/no-assertions as refusal probes must move to still-excluded inputs, retaining their catalog sizes and recording deliberate admissions. Public stage codes/messages/enum symbols remain unchanged.

Core adapter declaration lookup compares complete root expanded name; state identity remains per-compiled-schema object identity. Existing Core query environment/capability/lifetime guards are not broadened. Internal provider tests must exercise actual Core snapshot facts/atomization and foreign identity refusal; external consumers must exercise public assess/read/export and disposal. No Core runtime/API change is anticipated or approved by inference. No publication or release-controller change; the existing unpublished0.6 feature line remains, relative to published0.5beta.1.
