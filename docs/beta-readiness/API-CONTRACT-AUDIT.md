# Public API contract audit

17 November 2026. Published baseline0.5.0-alpha.0.7; source main d82e93d023233eb85b15ed203cb04f964054908d. [Inventory](API-INVENTORY.json), [caught characterization observations](OBSERVATIONS.json), [decision draft](CONTRACT-DECISIONS.md). This document records behavior and recommendations, not accepted beta contracts. No product source changed.

## Coverage and evidence

Reflection over the actual published-package runtime assembly reproduces all39 exported types and313 declared contract rows from the alpha review. Every type is classified in the inventory; the operation matrix groups constructors/properties/generated record members by contract rather than pretending313 rows are313 independent behaviors. Executed characterization is five caught cases against a PackageReference-only console consumer. It uses only synthetic XML and self-created temporary files, with no network resolver probes or unhandled negative cases. The five observations are additional audit evidence, not additions to the272-test catalog. Named existing tests below support specific contracts, not universal coverage.

## Reproduced findings and proposed action

| ID | Observation | Interpretation | Proposed beta action |
|---|---|---|---|
| A01 | No-assertion schema + unknown root -> IsValid=true | Legacy assertion helper, not full validation | Document prerequisite compile-diagnostic checks and assertion-only result; design explicit refusal/wrapper contract before changing behavior |
| A02 | Not-schema compile diagnostics exist; Validate returns IsValid=true | Compile diagnostics are not carried into validation result | Add targeted regression and decide diagnostic propagation/precondition, not arbitrary structural certification |
| A03 | Compiler Assertions runtime list is writable | Immutability wording exceeds shallow IReadOnlyList surface | Define defensive immutable snapshots, including nested collections; assess constructor compatibility |
| A04 | Directory helper opens ../outside.xsd | Directory preference is not containment; external stylesheets can select other readable files | Qualify explicit restricted resolution first; define canonical path/link/fallback policy and failure behavior, retain compatibility consciously |
| A05 | Text allowlist prefix /allowed admits /allowed-sibling | Text-prefix matching, not directory allowlist | Provide explicit containment policy if required; don't silently reinterpret arbitrary URI prefixes without compatibility review |

A04/A05 used only diagnostic-created temporary marker files and closed streams before nonrecursive cleanup. No user/private files read. These observations do not establish remote exploitation or claim any bypass of the native parser. A01/A02 are not evidence of false Valid from NativeDecimalSession.

## Remaining evidence

No fuzz campaign, full hostile-input matrix, actual time/memory benchmark, arbitrary concurrent schedule, full conformance corpus or positive cross-universe proof was run. Root Stream byte budgets, caller reader policy, diagnostic leakage, nested collection aliasing and resolver encodings/links/fallback need explicit B03 coverage. Proposed first implementation slice: resolution policy hardening with paired legitimate-file/escape/fallback tests, preceded by recorded immutable semantic basis and compatibility decision. Then immutable descriptor snapshots and explicit legacy-result semantics. The current recommendation remains alpha until decisions and evidence meet the checklist.
