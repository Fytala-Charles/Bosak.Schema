# Bounded abstract global element declarations

Both owned native facades admit abstract on existing supported global element declarations. XML Boolean true/false/1/0 values use whitespace collapse and the256UTF16 source bound. Invalid admitted Boolean lexical forms are Invalid; excess capacity is Unsupported. Omitted/false/0 flags keep ordinary behavior.

Abstractness is frozen in an immutable set of canonical global declaration identities after compilation. It never belongs to shared types or to an expanded name alone. An unused abstract declaration therefore does not invalidate a concrete declaration sharing its type, or a same-named local particle.

Direct use of an abstract declaration is Invalid at a root, through a referenced particle, or when a known global is matched beneath anyType lax content. Root/scalar/container/known-lax dispatch checks the original canonical declaration before xsi:type/nil handling can admit it. Failure publishes no document/facts; later concrete assessment recovers without changing compiled metadata. False declarations preserve original governing/actual type and declaration evidence.

Substitution groups, local abstract attributes and abstract complex-type definitions remain Unsupported. This adds validation behavior, not a public abstract-flag accessor or full PSVI/C45 surface. Existing schema/type/content/value/namespace constraints, no augmentation, nillability and all finite limits remain. Original XML export, cancellation, foreign authority and expiry remain. Legacy decimal-only grammar remains unchanged.

For example, abstract global `a` and concrete global `b` may share xs:decimal. `<a>1</a>` is Invalid while `<b>01.20</b>` retains decimal1.2 and the original b declaration. A local `a` inside another owner remains concrete because it is a different declaration.
