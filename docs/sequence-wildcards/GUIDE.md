# Bounded sequence-owner attribute wildcards

Both owned native facades admit one direct strict/default-strict anyAttribute on an existing finite explicit nonempty xs:sequence complex owner. Anonymous/named roots, nested sequence containers, named-root aliases and global references retain original declarations/types and compiled wildcard plans. Existing namespace matching and notNamespace/notQName/##defined exclusions apply; explicit uses take precedence and all other attributes require actual supported global declarations. Known attribute types/fixed/identity rules and child order/occurrence/value checks remain independent.

Element-only owners have no typed value, including when all optional children are absent. They are not empty-content types and do not become empty strings or zero-item values. Child scalar and attribute projections retain their existing indexes and original member/type evidence. All validation completes before facts publish; invalid attributes/children/references or capacity refusals return no partial assessment. No missing default/fixed attributes are inserted. Original XML, ownership, cancellation and expiry remain.

The extension excludes mixed/simple-content/all/choice owners, top-level group shorthand, wildcard+assertion combinations, inheritance/composition and lax/skip. Existing empty-owner support is unchanged. The legacy decimal-only grammar still refuses wildcard syntax. Existing sequence/schema budgets, actual document64elements/depth4/64application attributes/16per owner, eight256UTF16 namespace/QName tokens and numeric/string/identity/fact limits remain. Special XML/XSI requests retain their previous refusals.
