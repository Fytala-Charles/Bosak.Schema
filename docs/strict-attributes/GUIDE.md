# Bounded strict attribute wildcard guide

Both owned native facades admit one direct anyAttribute on an existing empty complex owner: anonymous/named roots, nested sequence terminals and global references. Omitted processContents means strict. Namespace constraints support omitted/##any, ##other, ##local, ##targetNamespace and lists of absolute namespace URIs/local/target tokens. Namespace-other excludes both the target namespace and absent namespace. Finite lists have at most eight tokens of256UTF16; relative URI constraints are Unsupported.

Explicit attribute uses take precedence even if their namespace does not match the wildcard. Every remaining attribute must match the namespace constraint and resolve to a supported original global declaration; otherwise Invalid. Its actual type, fixed constraint and document ID/IDREF semantics still apply. Explicit uses retain their existing order, followed by wildcard globals in schema source order. XML order and values remain original; missing global defaults/fixed values are not inserted. Empty complex owners keep zero typed items and their original declarations/types.

Lax/skip, notNamespace/notQName, group/inheritance wildcard composition, nonempty/mixed owners and wildcard+assertion combinations remain Unsupported. Special XML/XSI requests retain existing refusals. Location hints are not fetched. Schemas containing this wildcard preflight actual document64elements/depth4/64application attributes/16attributes per owner; existing numeric/string/identity/fact capacities, cancellation, ownership and expiry still apply. Unsupported or Invalid assessments publish no partial facts.
