Admit global simpleType(name) containing exactly restriction(base QName resolving to xs:decimal), with zero or more selected facets: minInclusive/minExclusive/maxInclusive/maxExclusive/totalDigits/fractionDigits, at most once each. Facets have value only and no element/text content beyond whitespace/comments/PIs admitted by the existing schema-node parser. Shared combined16global simple+complex type ceiling and16roots. Compile all definitions, including unused ones; all QName contexts are actual declaration-site bindings. Root scalar/simple types, user-defined bases/chains, anonymous simple types, lists/unions, new datatypes, explicit whiteSpace/fixed/id/annotations, pattern/enumeration/assertion facets, attributes/imports/nested structures stay refused. These are intentional profile restrictions.

Bounded integer facet parsing: XML whitespace collapse; signed ASCII integer lexical forms including + and leading zeroes, with negative zero permitted for fractionDigits. Value lexical text <=256characters; parse BigInteger then require totalDigits1..256/fractionDigits0..256. Out-of-range positive magnitudes above256 => Unsupported/RepresentationCapacity; malformed, negative or forbidden-zero values => Unsupported/ValueType. Range facet decimal literals use existing256lexical-character and explicit supplied digit/scale limits; bad lexical => Unsupported/ValueType, capacity => RepresentationCapacity. Scale alignment uses only parsed <=256character decimal values: at most256scale difference and512coefficient digits for exact comparison temporaries; no unbounded powers from facet integer values.

On normalized exact decimal c/10^s (s>=0, nonzero c has no fractional trailing zeros; zero is c=0,s=0), fractionDigits=f requires s<=f; totalDigits=t requires max(decimal digit count(abs(c)),s)<=t, with zero digit count1. This implements the normative |i|<10^t and0<=n<=t equation. Therefore0.001 needs totalDigits>=3 even though coefficient=1. Supplied lexical zeros affect representation capacity before normalization but not facet value validity.

Lower<=upper is required when both inclusive or both exclusive; strict lower<upper is required for mixed inclusive/exclusive bounds. Equal exclusive endpoints are a valid empty value space under4.3.8.4; compile succeeds and every present leaf fails validation. Equal inclusive endpoints admit the singleton. Do not reject other empty intersections (e.g. fractional digit restriction and interval) just for emptiness. Direct primitive base has no inherited user facets; chains/fixed facets remain excluded.

Existing instance lexical/digit/scale gates run before facet checks. Supported facet failures => Invalid with no owned document. Compile duplicate shared names/duplicate facet or wrong shape => Unsupported/DeclarationShape; unresolved/unsupported base/leaf and inconsistent component values => ValueType; excluded attributes => Attributes; explicit ceilings => RepresentationCapacity. Unknown facet names => ValueType. Existing paths/stage codes/messages/enum symbols and malformed XML outcomes stay unchanged outside deliberate admissions. Never ignore unused invalid definitions or fall back to another validator.

A named decimal leaf retains its named type in facts, node annotations and declared/actual atomic provenance; primitive decimal remains a separate handle even if no primitive leaf is present. Root named complex types retain FOTY0012. Use current Core APIs; no engine/pin/public API/relations/positive cross-universe acceptance is added. Source/package/retained qualification and authored clause-mapped cases follow; no official W3C/full conformance or publication is implied.
