# Recommended next contracts

These are proposals only: record immutable adoption and qualify feasibility before implementation. Observed refusal counts are not promised admissions; first refusals and additional co-blockers are nonexhaustive.

1. Bounded explicit suffix open content feasibility. Review original explicit/default applicability, owner models and wildcard validation separately. Start with an existing finite element-only sequence and a bounded suffix wildcard; preserve original known declaration/type authority, physical order, namespace constraints, occurrence/atom/source/lifetime limits, complete validation and no-facts failure. Do not silently include interleave, defaultOpenContent, general wildcard grammar, mixed-empty owners or unrelated derivation. The original open-content group remains evidence, not a forecast.
2. Frozen closed-catalog preflight. Establish which original include/import dependencies actually exist in the frozen source and which current catalog routes apply. Record exact upstream revisions and original bytes; do not invent missing schemas or count authored dependency variants as original admissions. Existing include/import support does not imply chameleon, foreign-complex, redefine or version breadth. This preflight can rank blockers without adopting new assembly semantics.
3. Typed integer/string assertion-facet contract. Define the original $value type/sequence/context and bounded grammar independently of legacy assertion helpers and general XPath. List-complex assertions and attribute contexts remain separate.
4. Profile/API freeze and exact-package beta preparation after those contract decisions. Do not wait for full XSD 1.1 to offer a useful bounded beta, but require explicit exclusions and a reviewed supported profile. Keep general C45/PSVI acceptance separate.

Named-integer restrictions, QName facet compatibility and self-contained default-group cases from the preceding ranking have been delivered. The two remaining default-attribute originals depend on broader foreign-complex composition; default use support alone is insufficient. General identity/substitution, type alternatives, NOTATION, unbounded particles, wider regex, anyType xsi:type and complex value constraints remain independently ranked gaps.
