# Known-declaration anyType lax matches

26November2026. Development Schema0.20 on signed Core1.86.0.

The builtin anyType element/attribute wildcards use namespace-any and lax processContents. This profile now admits a bounded subset: every encountered child element and application attribute must have an original supported global declaration in the closed catalog. Known declarations are validated using their actual existing plans/types. Bad known data is Invalid rather than silently skipped or read as an untyped string. Unknown names remain Unsupported; this is not complete lax assessment.

For example, declare root r with implicit/explicit anyType and global d as decimal. `<r>pre<d>01.20</d>post</r>` retains root aggregate `pre01.20post` as one untypedAtomic string and reads child d as exact decimal1.2. `<d>bad</d>` is Invalid. `<unknown/>` is Unsupported. Global declarations are selected by expanded name, not by unrelated same-name locals. Wildcard occurrences can repeat or appear in different order; they reuse the same original global component, not invented per-match declarations.

Application attributes use original global declarations, types and provided fixed/value rules. Attribute read indices follow global source declaration order within each owner, independent of physical XML attribute order; export preserves original XML order. Owner paths and original type/member authority remain. Missing global declarations with default/fixed metadata do not create attribute uses and do not augment anyType. Known ID/IDREF/IDREFS values participate in the existing document-wide table before fact publication.

Known simple children, empty/sequence/mixed/simple-content complex plans and nested anyType owners reuse existing supported validation routes, original nil/empty/list/union semantics and component handles. All/choice complex plans encountered beneath anyType remain Unsupported. Outer strict sequences preserve absent typed value/FOTY0012; anyType aggregates remain actual untypedAtomic values with original text/CDATA/whitespace/comments/PIs intact.

Schemas containing anyType preflight actual document limits before recursive assessment:64element nodes, depth4,64application attributes and16application attributes per owner. After local validation,16value-bearing element states are allowed, including every anyType mixed aggregate. Empty complex states do not consume this value budget. Existing stringUTF16, numeric/list/item, schema/component, XML/export and caller query limits remain. Excess is Unsupported without truncation or partial document/facts. Late invalid/unknown content, cancellation and owner disposal retain existing recovery and lifetime boundaries.

Explicit xs:any/xs:anyAttribute syntax and its namespace/notNamespace/notQName/UPA combinations, skip/strict modes, unknown/declaration-absent lax nodes, wildcard component projection and full PSVI are not added here. The current fact publisher requires a governing declaration for every issued fact; unknown nodes require a separately adopted representation instead of fabricated authority. Non-self anyType xsi:type, complex nil/default/fixed/derivation and full type closure remain excluded. Legacy grammar, public API and signed Core pin are unchanged; no publication or fullXSD1.1/C45/general schema-aware query acceptance is implied.
